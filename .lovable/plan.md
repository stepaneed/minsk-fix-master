## Разделение типов и новый раздел «Услуги»

Сейчас `service_types` хранит и виды ремонтируемой техники, и доп. услуги (выкуп / продажа восстановленной / запчасти). Это разные сущности с разной логикой страниц, форм и админки. Разделим их.

### 1. База данных

**Новые таблицы:**

- `extra_services` — каталог доп. услуг (выкуп, продажа техники, продажа запчастей)
  - `slug`, `title`, `description`, `kind` (`buyout` | `refurbished` | `parts`), `icon_url`, `cover_url`, `is_active`, `sort_order`, `settings jsonb` (для коэффициентов калькулятора и др.)

- `products` — товары для «Продажа восстановленной техники» и «Продажа запчастей»
  - `service_id` → `extra_services.id`
  - `title`, `slug`, `description`, `price`, `old_price` (для скидки), `discount_percent` (вычисляемое или ручное), `is_active`, `sort_order`
  - `attributes jsonb` — гибкие параметры товара (бренд, модель, состояние, ёмкость, цвет, мощность и т.д.); ключи фильтруются динамически

- `product_images` — несколько изображений на товар
  - `product_id`, `url`, `role` (`main` | `top` | `left` | `right` | `other`), `sort_order`

**Чистка `service_types`:**
- Удалить добавленные ранее записи с `category='service'` (`buyout`, `refurbished`, `parts`) — они переезжают в `extra_services`.
- Колонку `category` оставляем (на будущее), но фактически на сайте все `service_types` = ремонт.

**Сидинг `extra_services`:** 3 записи (buyout, refurbished, parts) с дефолтными иконками/обложками.

**Калькулятор выкупа — настройки в `extra_services.settings`:**
```json
{
  "base_coefficients": { "washing_machine": 150, "fridge": 200, ... },
  "age_multipliers": { "<3": 1.0, "3-7": 0.7, "7-12": 0.4, ">12": 0.2 },
  "condition_multipliers": { "working": 1.0, "minor_issues": 0.7, "broken": 0.4 },
  "brand_bonus": { "bosch": 1.1, "miele": 1.2, ... }
}
```

### 2. Публичные страницы

- `/services` — оставляем как сейчас (только ремонт техники).
- Новый раздел **«Услуги»** (доп.) — отдельный блок на главной + на странице услуг, ведущий на:
  - `/extra/buyout` — описание + калькулятор оценки (выбор типа техники, бренда, возраста, состояния → итоговая сумма; CTA «Оставить заявку»).
  - `/extra/refurbished` — каталог восстановленной техники с динамическим фильтром.
  - `/extra/parts` — каталог запчастей с динамическим фильтром.
- `/extra/$kind/$productSlug` — карточка товара: галерея (главное + top/left/right + остальные), цена со скидкой, характеристики, кнопка заявки.

**Динамический фильтр:** строится из `attributes` оставшихся в выборке товаров — показываются только те ключи и значения, которые есть в текущем пуле (как на маркетплейсах).

### 3. Форма заявки

`OrderForm`: сейчас выпадающий список тянет всё подряд. Разделим на 2 группы (`optgroup`): «Ремонт техники» и «Услуги». Тип заявки сохраняется (`type_id` для ремонта или `extra_service_id` + `product_id` опционально).

Добавим в `orders` поля: `extra_service_id`, `product_id` (nullable).

### 4. Админ-панель

Новые пункты меню:
- **Доп. услуги** (`/admin/extra-services`) — список buyout/refurbished/parts, редактирование заголовка/описания/иконки/обложки, тумблер активности.
- **Калькулятор выкупа** (`/admin/buyout-calculator`) — редактор JSON-коэффициентов с дружелюбными полями (таблицы коэффициентов по типам, возрасту, состоянию, брендам).
- **Товары** (`/admin/products`) — CRUD товаров:
  - выбор `extra_service` (refurbished/parts),
  - название, slug, цена, старая цена (для скидки), описание,
  - **атрибуты** — редактор пар «ключ: значение» (свободные ключи),
  - **изображения** — мультизагрузка, у каждой роль (main/top/left/right/other) и порядок.
- **Виды техники** (`/admin/service-types`) — остаётся, но без `category` (только ремонт).

### 5. Технические детали

- Таблица `products` + `product_images` + `extra_services` под публичным чтением (`SELECT to anon`), запись только admin (RLS как у `brands`).
- Хранение изображений — bucket `admin-images` (уже есть).
- Калькулятор — клиентский расчёт по конфигу, который тянется из `extra_services.settings` (kind='buyout').
- Динамический фильтр — реализован клиентом: загружаем все активные товары услуги, строим набор фильтров из `attributes`, после применения пересчитываем доступные значения.
- Карточка товара: галерея — Embla carousel (уже используется в проекте через `ui/carousel`).

### 6. Объём работ

Миграция БД (3 таблицы + сид + правки `orders`), 5 новых публичных роутов, 3 новых админ-роута, правки `OrderForm`, `Header` (меню), `AdminShell` (меню), общий компонент `ProductFilter`, `ProductGallery`, `BuyoutCalculator`.
